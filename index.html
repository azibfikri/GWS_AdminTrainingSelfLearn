Module 0 · Foundations

Goal: build the mental model everything else hangs on.

In plain English
Google Workspace is the company’s email, files, meetings, and chat — all in Google’s cloud. Your job as admin is not to run servers. Your job is to configure people, rules, security, and support. The Admin console (admin.google.com) is your control room.

0.1 Editions (plans)

Editions differ by storage, security, and compliance features. Exam loves to ask: “Can this edition even do that?”

EditionBest forRemember
Business Starter / Standard / Plus Small–mid companies (Business capped ~300 seats) Plus is the hands-on tier: Vault + advanced endpoint mgmt. Storage grows by tier (~30GB / ~2TB / ~5TB pooled per user — verify in Billing).
Enterprise Standard / Plus Bigger orgs Adds DLP for Drive/Chat, context-aware access, Security Center / Investigation tool, S/MIME, data regions. Many exam features are Enterprise.
Frontline Shift / deskless workers Lightweight, low-storage seats. Licensing-fit scenarios.
Education Schools Same console ideas; education licensing + safety extras.
Cloud Identity (Free / Premium) Identity only Users, groups, SSO, 2SV, devices — no Gmail/Drive seat. For non-Workspace users or identity-only licensing.
Exam tip
If a question mentions DLP, context-aware access, data regions, or the investigation tool — first check whether the stated edition includes it. The “correct” action may be unavailable on Business Starter.

Storage is pooled

Analogy
Imagine one big company water tank. Every license adds water to the tank. Anyone can drink from it until the tank is empty (or you set per-person limits). Low storage? Add licenses, set quotas, or free space — not “upgrade one mailbox.”

0.2 Admin console map

Directory

Users, Groups, OUs, Buildings & resources, company profile.

Apps

Gmail, Drive, Calendar, Meet, Chat, Gemini + Marketplace + SSO apps.

Security

2SV, passwords, CAA, API controls, DLP, Security center, Alert center.

Devices / Reporting / Billing / Account

Phones & Chrome · logs & reports · licenses · domains, roles, data regions, migration.

Speed tip
Use the top search bar (“DKIM”, “retention”, “2SV”). Away from computer? Google Admin mobile app can suspend users, reset passwords, view alerts.

0.3 The #1 mental model: Org → OUs → Users (+ Groups on top)

In plain English
Organizational Units (OUs) = folders in a company tree. Every person sits in exactly one folder.
Settings on a parent folder flow down to children (inheritance) unless a child overrides them.
Groups = sticky notes that can sit on people from many folders. One person can be in many groups.
Use an OU when…Use a Group when…
Setting follows structure; service on/off; one clear answer per person (e.g. disable Chat for Warehouse). Membership cuts across departments or changes often; layering an exception (e.g. Gemini pilot for mixed teams).
Rule of thumb
OUs answer “who is this person, structurally?” Groups answer “what are they allowed to do, regardless of where they sit?” If OU + group policies conflict → group usually wins (most specific group wins when several apply).

0.4 How a setting reaches a user

  1. Service must be On (org / OU / group).
  2. Start from org default → apply user’s OU (inheritance) → apply group overrides.
  3. Console shows the effective value for the scope you selected — always check that.
  4. Most changes take minutes; some up to 24 hours. “Nothing happened” = wrong scope or waiting for propagation.

Manual 0A · Find any setting and confirm who it applies to

  1. Go to admin.google.com as an admin.
  2. Type the setting in the top search bar (faster than menus).
  3. On the page, use the Organizational units / groups selector on the left — that is whose settings you are editing.
  4. Pick the top org (everyone), a child OU, or a group overlay → Save.
  5. Propagation is often minutes, sometimes up to 24 hours. “Nothing happened” = wrong scope or still waiting.

Module 1 · Users, Domains & Directory ~20%

Goal: manage the full life of an account — create, change, suspend, delete, archive — plus domains, groups, and rooms.

In plain English
Every employee account has a life story: born (provisioned) → works → maybe put on leave (suspend) → leaves the company (delete or archive). The exam hammers what happens to data and licenses at each step.

1.1 User life cycle (memorize this)

StateCan sign in?Data & license
ActiveYesUses a full license. Full access.
SuspendedNoData kept. License still used. Instantly reversible. Best for leave / investigation.
DeletedNoRecoverable 20 days, then gone. Transfer Drive first. License freed.
Archived (AUL)NoCheaper Archived User License. Vault can keep data without a full seat. Ideal for ex-staff under retention.

Clean off-boarding order

  1. Suspend immediately — cuts access, destroys nothing.
  2. Reset password / sign out sessions (Session Control).
  3. Transfer Drive (and other) data to manager/successor.
  4. End state: delete (reclaim license) or Archived User License (keep data cheap for Vault).
Exam tip
Cheap + keep ex-employee data → Archived User License. Need them back / still investigating → suspend. Truly gone + data transferred → delete (20-day window).
Common pitfall
Deleting before transferring Drive ownership = classic data-loss mistake. Shared Drive files belong to the team — no transfer needed.

1.2 Creating users & provisioning tools

Small batches: manual or CSV. Ongoing / large: sync or SCIM. Match the tool to the source of truth.

MethodWhenNotes
Manual / CSVOne-off, small batchesNo sync
GCDSOn-prem LDAP / Active DirectoryOne-way AD → Workspace; you install a connector
Directory SyncCloud IdP (e.g. Entra ID)Google-hosted; no server
SCIM + SAMLIdP (Okta/Entra) owns accounts + loginSCIM = create/update/disable; SAML = sign-in. Workspace is SP.
Admin SDK / APICustom automationProgrammatic
Exam tip — sync vs migration
Sync tools move identities. Migration tools (DMS) move content (email/files). Don’t mix them up.

1.2b SSO (SAML)

Analogy
The Identity Provider (Okta/Entra) is the nightclub bouncer with the guest list. Google trusts the bouncer’s stamp (SAML assertion) and lets the person in. Keep a break-glass Super Admin that bypasses SSO so you’re never locked out if the IdP dies.

1.3 Aliases, rename, OU moves

  • Email alias = extra address → same mailbox. No extra license.
  • Rename primary email keeps old address as alias so mail still flows.
  • Separate mailbox = separate user + license.

1.5–1.6 Licenses & passwords

Licenses can be automatic (everyone gets a seat) or manual (per user/OU/group). Can’t reach a paid service? Check license first. Password rules live under Security → Authentication → Password management.

1.7 OU design

Design OUs for how policies differ, not the org chart. Fewer purpose-built OUs beat deep confusing trees. Common pattern: Standard staff · High-security · Shared/Kiosk · Contractors + groups for exceptions.

1.8 Groups

TypeWhat it’s for
Distribution listEmail many people via one address
Collaborative InboxShared queue (support@) — take / assign / resolve
Dynamic groupMembership from a query (department = Sales) — auto-updates
Security groupAccess/security policies, not just email

Also control: who can join, post, view members, and whether outsiders can post.

1.9 Domains

TypeMeaning
PrimaryMain company identity
SecondarySeparate set of user accounts on another domain (each needs a license)
Domain aliasEvery existing user gets an extra address — no new accounts, no extra licenses

Verify ownership with TXT (or CNAME / HTML / meta / MX), then add MX for mail. Walk it click-by-click in the domain & mail demo.

1.10 Buildings & resources

Rooms/equipment under Directory → Buildings and resources. Become bookable calendars. “Add 200 rooms across 10 sites” → CSV bulk upload, not one-by-one.

Where to click · Manuals 1A–1L

1A · Create a single user

Directory → Users → Add new user

  1. First/last name and primary email; pick the correct OU (this drives every inherited policy).
  2. Auto-generate or set a password; tick “Ask for a password change at next sign-in.”
  3. Add new user, then share sign-in details securely.

1B · Bulk-create from CSV

Directory → Users → Bulk update / Import users

  1. Download the CSV template so headers match exactly.
  2. One row per user: first name, last name, email, password, org unit path.
  3. Upload → fix flagged rows → confirm. Tens to a few hundred users. Larger / ongoing → GCDS, Directory Sync, or SCIM.

1C · Add an email alias

Directory → Users → user → User information → Alternate email addresses

  1. Add an alias on a domain you own and save. Mail lands in the same mailbox. No extra license.
  2. Rename primary keeps the old address as an alias so mail still flows.

1D–1F · Suspend, transfer, delete (20-day window)

Directory → Users → More options → Suspend · Transfer data · Delete · Deleted users

  1. Suspend (or toggle Suspended) to cut access instantly; Reactivate to restore.
  2. Transfer Drive (and Sites etc.) to a manager before delete — skip this and My Drive can be lost.
  3. Delete user → restore within 20 days from Deleted users. Or use Archived User License to keep data cheap for Vault.

1H · Reset a password

Directory → Users → user → Reset password

  1. Auto-generate or type a temporary password.
  2. Enable “Ask for a password change at the next sign-in.” Org rules live under Security → Authentication → Password management.

1I · Create an OU and move users

Directory → Organizational units → Create · then Users → Change organizational unit

1J · Create a group

Directory → Groups → Create group

  1. Name, group email, owner; optionally flag as a Security group.
  2. Access settings: who can join, post, view members, whether outsiders can post.

1K · Add and verify a domain

Account → Domains → Manage domains → Add a domain

  1. Choose secondary vs alias.
  2. Publish the TXT (or other) verification → Verify.
  3. Then add MX so mail can flow (Module 2).

1L · Create a bookable room

Directory → Buildings and resources → Add building → Add resource (Meeting space)

  1. Name, building/floor, capacity, features (video, whiteboard). It becomes a resource calendar.
  2. “200 rooms across 10 sites” → CSV bulk, not one-by-one.

Module 2 · Core Workspace Services ~23%

Goal: configure Gmail, Drive, Calendar, Meet, Chat, Gemini — and know where each toggle lives.

2.1 Gmail

In plain English
MX records tell the internet “deliver our mail to Google.” That’s inbound routing only. Outbound spam problems are almost always missing SPF + DKIM + DMARC — not a random Gmail toggle.
RecordDNSWhat it proves
MXMXWhere inbound mail goes (smtp.google.com or legacy ASPMX set)
SPFTXTWhich servers may send as your domain
DKIMTXTCryptographic signature — message wasn’t altered and is yours
DMARCTXT (_dmarc)What receivers do if SPF/DKIM fail (none → quarantine → reject) + reports
Exam tip
Outbound mail lands in spam → finish SPF + DKIM + DMARC. Start DMARC at p=none (monitor), then tighten.

Routing & compliance

  • Content / attachment compliance — match words/patterns/types → quarantine, reject, modify, BCC, footer.
  • Dual / split delivery — copy to another system or split Google vs legacy during migration.
  • Inbound/outbound gateways — relay through a third-party filter.
  • Spam / phishing / malware — allowlists, denylists / blocked senders, approved senders.
  • Security Sandbox — detonates attachments before delivery (unknown malware).
  • Attachments: send up to ~25 MB (bigger → Drive link). You can block specific file types.
  • Access — toggle automatic forwarding and POP/IMAP per OU (turn off to reduce leak risk).
  • Compliance footer & admin quarantine — disclaimer on outbound; suspicious mail for review.
  • Delegation — assistant reads/sends on someone’s behalf.

Migration

Data Migration Service (DMS) moves email/calendar/contacts from Exchange/M365, IMAP, or another Workspace. Migration = content. Sync = identities.

2.2 Drive & Docs

My Drive

Owned by a person. Must transfer when they leave.

Shared Drive

Owned by the team. Survives off-boarding. Prefer for org content.

Shared Drive roleCan roughly do
ManagerEverything incl. members & delete drive
Content managerAdd/edit/move/delete files; not membership
ContributorAdd/edit; limited move/delete
Commenter / ViewerComment only / view only
  • Sharing defaults: internal vs external; warn/block outside shares.
  • Target audiences — safer “share with All of Company”-style suggestions.
  • Trust rules — precise who-can-share-with-whom (Module 3).
  • Pooled storage + per-OU quotas.
  • Drive for desktop — allow or block the sync client per OU.
  • Offline access — enable/disable per OU; labels classify (Module 3).

2.3 Calendar

  • Internal/external sharing defaults; block invite spam from unknowns.
  • Resource calendars from Buildings & resources + booking rules/delegates.
  • Calendar delegation for assistants; transfer event ownership when organizer leaves.

2.4 Meet

Exam tip
Unwanted guests / join problems → Meet safety (host controls, knocking, org-only).
Bad audio/video → Meet quality tool (Module 6), not safety.

2.5 Chat

History on/off matters: if history was off, Vault can’t retain what never existed. Control spaces, external chat, moderation, approved bots.

2.6 Gemini

  • Org prompts/content are not used to train Google’s foundation models.
  • Enable per OU; pilot with a group first.
  • Extensions let Gemini act across Gmail/Drive; use usage reports for adoption.

2.7 AppSheet vs Apps Script

No-code app from Sheets/Drive → AppSheet. Custom JavaScript glue → Apps Script.

Where to click · Manuals 2A–2C

2A · Point a domain’s mail to Google

DNS host → MX · then activate Gmail in the Admin console

  1. Remove old MX records.
  2. Add Google MX — modern smtp.google.com priority 1, or the legacy ASPMX set if instructed.
  3. Save DNS; allow propagation; activate Gmail for the domain; send a test in and out.

Open the domain & mail demo to click this path: Admin → DNS host → inbox.

2B · Turn on DKIM

Apps → Google Workspace → Gmail → Authenticate email

  1. Select the domain → Generate new record (2048-bit if DNS allows).
  2. Publish host/value as a TXT at your DNS host.
  3. Back in the console → Start authentication. Then publish SPF and a DMARC policy (start p=none).

2C · Create a Shared Drive and add members

Apps → Drive and Docs → Manage Shared Drives → Create

  1. Name it; add members: Manager, Content manager, Contributor, Commenter, Viewer.
  2. Files are team-owned — they survive off-boarding. My Drive files do not.

Module 3 · Data Governance & Compliance ~15%

Goal: retain, protect, classify, and export data — and know which tool does which job.

3.1 Google Vault

In plain English
Vault is the company’s legal filing cabinet for Gmail, Drive, Chat, Meet recordings, Groups. It is not a user backup/restore button. It’s for retention, legal hold, and eDiscovery.
  • Retention rules — auto keep/purge by service, date, scope (default + custom).
  • Holds — freeze data for litigation; live inside a Matter (case folder). Hold always beats retention deletion.
  • Search & export — find and export with metadata for lawyers.
  • Vault audit — who searched/exported/changed holds.
Big Vault facts
1) Hold wins over retention delete.
2) Keep ex-employee data cheap → Archived User License.
3) Vault ≠ backup for users.
4) Chat/Meet only retainable if history/recording was on when created.

3.2 DLP (Data Loss Prevention)

Analogy
DLP is a security guard reading documents as they leave the building. Sees a credit card number? Blocks, warns, or logs it.

Detectors (credit card, SSN, custom regex/word lists) + actions (block / warn / audit) + scope (OU/group). Drive DLP on share; Gmail on outbound; Chat on messages/uploads. Advanced Drive/Chat DLP = Enterprise.

3.3 Drive trust rules

Granular sharing control: OU ↔ OU, group, domain, user; external + visitors. Answer for “Legal may share with outside counsel’s domain, but nobody else may share externally.”

3.4 Export & residency

ToolUse when
Google Takeout (user)User self-exports own data — often restricted
Data Export tool (Super Admin)Export entire org (waiting period) — big “get everything out”
Vault exportTargeted eDiscovery for a matter
Data regionsStore covered data at rest in US/Europe etc. by OU

3.5 Labels

Tags like Public / Internal / Confidential. User-applied, default, DLP-driven, or AI classification. Labels bridge classification → enforcement: label “Confidential” then DLP/trust rules act on it.

Where to click · Manuals 3A–3C

3A · Create a Gmail retention rule

vault.google.com → Retention → Custom rules → Create

  1. Choose service (Gmail) and scope (org, OU, or accounts).
  2. Set duration and what happens after (keep or purge). A default rule covers everything; custom rules target subsets.

3B · Place a hold for an investigation

Vault → Matters → Create a matter → Holds → Create hold

  1. Pick the service and accounts/OU; optional search terms / date range.
  2. Save. Held data is never purged while the hold stands — even if retention would delete it.

3C · Block external sharing of credit-card numbers

Security → Access and data control → Data protection → Manage rules → Add

  1. Scope to OU/group; Drive trigger = file shared.
  2. Condition: predefined Credit Card Number detector (set a match threshold).
  3. Action: Block external sharing (or Warn); customize the user message; save. Advanced Drive/Chat DLP is typically Enterprise.

Module 4 · Security Policies & Access ~20%

Goal: protect sign-in, delegate admin power safely, watch threats, control which apps touch data.

4.1 Passwords & 2-Step Verification (2SV)

In plain English
Password = something you know. 2SV = second proof (phone prompt, authenticator, security key). Rollout: allow → set enforcement date → give new users an enrollment grace period.
MethodStrength
Security keys / passkeysStrongest, phishing-resistant — require for admins / high-risk
Authenticator / Google promptStrong + convenient
Backup codesEmergency one-time codes
SMS / phone callWeakest (SIM-swap) but better than none
Pitfall
Enforce 2SV with zero enrollment window → lock people out. Always pilot + grace period. Protect Super Admins hard; keep break-glass account.

4.2 Context-Aware Access (CAA)

Exam tip
2SV proves who you are.
CAA decides if the situation is allowed (managed device, corp network, country).
Words like device state / network / geography → CAA (often Enterprise).

4.3 Admin roles — least privilege

RoleCan do
Super AdminEverything — keep rare, strongest 2SV, not for daily work
User Management AdminCreate/suspend/reset non-admins — not critical security
Help Desk AdminPassword resets & basic help — deliberately limited
Groups / Services / Mobile / Reports…Scoped function
Custom rolePick only exact privileges; scope to OU if regional
Exam tip
Help desk resets passwords only → Help Desk Admin (or custom). Regional admin → role scoped to that OU. Never gift Super Admin for a narrow need.

4.4 Session control

How long web sessions last before re-login. Shorter for sensitive groups. Complements 2SV + CAA.

4.5 Security center toolkit

NeedTool
Quick health / gaps vs best practiceSecurity dashboard / health page
Investigate + remediate (delete mail, suspend, remove access)Investigation tool
Auto-notify when X happensActivity rule + Alert center

4.6 Apps, Marketplace, API access

  • Marketplace allowlist — only approved apps.
  • API controls (OAuth) — Trusted / Limited / Blocked; restrict Gmail/Drive scopes.
  • Workspace as IdP for SaaS via SAML (Web & mobile apps).
  • Connected apps — revoke tokens already granted.
Exam tip
Risky app already connected → block/Limited in API controls + remove token under Connected apps. Stop new junk installs → Marketplace allowlist.

Also control Additional Google services (YouTube, Maps, AdSense) per OU — not the same as Marketplace allowlist.

Where to click · Manuals 4A–4B

4A · Enforce 2SV for an OU

Security → Authentication → 2-step verification

  1. Select the OU/group.
  2. Allow users to turn on 2SV, then set Enforcement with a start date and a new-user enrollment grace period.
  3. Optionally restrict sensitive groups to security keys only. Never enforce with zero enrollment window.

4B · Create and assign a custom admin role

Account → Admin roles → Create new role

  1. Name it and select only the privileges required.
  2. Assign users (or service accounts), optionally scoped to an OU. Help desk resets → Help Desk Admin, not Super Admin.

Module 5 · Browsers & Endpoints ~10%

Goal: keep company data safe on phones, laptops, browsers — and off-board cleanly.

5.1 Mobile device management

ApproachWhat you get
BasicAgentless: screen lock + wipe corporate account. On by default.
AdvancedFull MDM: approval, stronger policies, apps, full device wipe. Needs compatible edition.
Third-partyIntune, Jamf, etc. if company already standardizes there.
Off-boarding wipe choice
BYOD / personal phone → account wipe (company data only, leave photos).
Company-owned → device wipe OK (factory reset).
Suspending the user also cuts mobile access immediately.

5.2 Chrome Browser Cloud Management (CBCM)

Enroll browsers with a token; enforce updates, Safe Browsing, homepage, extensions by OU/group — same inheritance model.

Exam tip
Finance must have extension X and can’t remove it → Force install on Finance OU/group.
Stop random extensions → block all, allow approved list.

Where to click · Manuals 5A–5B

5A · Turn on advanced mobile management

Devices → Mobile & endpoints → Settings → Universal (and platform) settings

  1. Select the OU → set management level to Advanced.
  2. Configure passcode, encryption, app management → Save. New enrollments in that OU follow the policy.

5B · Force-install an extension for a team

Devices → Chrome → Apps & extensions → Users & browsers

  1. Select the OU/group → find or add the extension by ID/URL.
  2. Installation policy: Force install (or Allow / Block). Stop junk → block all + allowlist.

Module 6 · Monitoring & Troubleshooting ~13%

Goal: find the right log fast, recover data, escalate cleanly.

6.2 Email troubleshooting

Email Log Search for delivery path (delivered / rejected / quarantined / in transit). Headers + SPF/DKIM/DMARC → Google Admin Toolbox (toolbox.googleapps.com) Messageheader tool. HAR file for support: Chrome DevTools → Network → Preserve log → reproduce → Save as HAR. Treat as sensitive.

6.3 Recovery windows (memorize)

ThingWindow
Drive Trash30 days, then auto-purged
Admin restore deleted Drive/Gmail data~25 days after that
Deleted user account20 days to restore, then permanent

Calendar, Drive and Meet troubleshooting

  • Calendar — Apple/Outlook sync, missing free/busy, or sharing problems are usually sharing defaults or account state — not a new product.
  • Drive — sharing permissions, Drive for desktop sync errors, offline access. Trash auto-purges after 30 days; admins can restore deleted Drive/Gmail for about 25 days after that.
  • Meet — bad A/V → Meet quality tool. Can’t join / random guests → Meet safety (Module 2), not the quality tool.

Where to click · Manuals 6A–6B

6A · Trace a message with Email Log Search

Reporting (or Apps → Gmail) → Email Log Search

  1. Filter by sender, recipient, subject, or date (last 30 days).
  2. Open a result for the delivery path: delivered / rejected / quarantined / in transit.
  3. Authentication failures → Admin Toolbox Messageheader (toolbox.googleapps.com) for SPF/DKIM/DMARC on the real headers.

6B · Generate a HAR file for support

Chrome DevTools → Network

  1. Tick Preserve log, reproduce the problem.
  2. Right-click the request list → Save all as HAR with content. Treat as sensitive — share only with Google Support.

6.4 Reports & support

Reporting → usage, storage, account/device activity for trends. Escalate well: repro steps + ELS/headers/HAR + Status Dashboard checked first + Workspace Updates / release calendar, then a Google Support case.

Module 7 · Exam Strategy

From the notes
50–60 multiple-choice & multiple-select questions · 120 minutes · scenario-based · about $125 (plus tax) · online-proctored or a test center · certification valid 3 years.
  • ~2 minutes per question; flag and move on; review flagged at end.
  • Multiple-select tells you how many — pick exactly that many.
  • Read for the constraint: only some users, minimise cost, managed devices, preserve data, edition limits.
  • Pick the most specific correct tool (least privilege, narrowest scope).
  • Beware distractors that exist but solve a different problem (safety vs quality, sync vs migration, dashboard vs investigation).
